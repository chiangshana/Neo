# 工廠訂單排程遺傳演算法說明

## 專案目標
這個專案的目標，是根據業主提供的訂單、BOM、製造效能、充填效能、機器限制與會議整理規則，建立一套可以快速重排的工廠排程程式。

目前演算法核心採用遺傳演算法（GA）：
- 染色體代表訂單排序
- 解碼器依排序逐張訂單安排調製、排瓶、充填日期
- 適應度以總加班分鐘數加上各類懲罰組成
- 先求可行，再逐步優化加班與排程品質

## 專案結構
目前建議只把下面幾類檔案視為正式交付內容：

- `genetic_algorithm.py`：GA 排程主程式，可用命令列執行，也提供 GUI 呼叫的 `run_scheduler()`。
- `ga_tkinter_app.py`：Tkinter 圖形介面，分成輸入資料、GA 參數、輸出格式、執行結果與打包流程。
- `build_installer.py`、`build_installer.bat`、`requirements-build.txt`：Windows 打包與安裝包產生工具。
- `README.md`：專案使用說明。
- `PROJECT_IMPROVEMENT_ROADMAP.md`：根據最新業主/老師回饋整理的下一版改進路線。
- `workbook_bom_refresh.xlsx`：目前測試與正式版使用的整理後 workbook。
- `calendar_capacity.xlsx`：固定輸入格式，供業主調整每日產能、週末與假日排除。
- `ga_report_*.md`、`ga_third_report.pptx`、`ga_report_template.pdf`：報告與簡報輔助資料。

每次執行 GA 產生的 `ga_output*`、`ga_cleanup*`、`ga_review*`、`ga_calendar_export*` 等資料夾都是可再生輸出，不建議當成原始專案檔案管理。

## 圖形介面使用方式
如果不想用命令列，可以直接使用 Tkinter 圖形介面：

```powershell
python -B ga_tkinter_app.py
```

Windows 也可以直接雙擊：
- `run_ga_gui.bat`

介面分成七個區塊：
- `總覽`：新的操作入口，集中顯示目前狀態、本次設定摘要、建議下一步與常用操作按鈕。
- `輸入產能日曆`：業主日常只需選擇 `calendar_capacity.xlsx`；訂單、製造效能與充填效能使用打包內建的基礎 workbook。
- `GA 參數`：調整族群大小、世代數、突變率、交配率與 seed，也可一鍵套用 quick run、demo 或正式版參數。
- `輸出格式`：選擇輸出資料夾基底，並查看精簡交付檔與完整原始輸出的用途。
- `開發者設定`：視覺化調整企業資料表、固定產能日曆、排除假日、手動凍結排程、換線時間、批次/拆單假設、噴印機數量與每日 16:00 重排。
- `執行結果`：啟動 GA、即時查看執行紀錄，完成後可直接開啟排程檢查報告、當日排程確切時間、輔助檢查資料與 Google 日曆檔。
- `打包安裝包`：維護者可直接從 GUI 啟動 PyInstaller/Inno Setup 打包流程。

### 統一輸入格式
GUI 的 `輸入產能日曆` 頁已調整為業主日常操作只輸入一份檔案：

- `calendar_capacity.xlsx`：固定產能日曆，工作表名稱固定為 `calendar_capacity`。

訂單資訊、製造效能與充填效能目前視為程式內建基礎資料，打包時會隨 `workbook_bom_refresh.xlsx` 一起放進程式資料夾。這樣 demo 或業主日常重排時，不需要再手動選擇主 workbook，避免把 `calendar_capacity.xlsx` 誤選成訂單資料。

內建基礎 workbook 仍維持三類資料，供開發者維護與檢查：

- `訂單時間`：建議工作表為 `時間準備表V1`、`X2023訂單資訊含入庫日` 或 `2023訂單資訊`。至少要能提供訂單編號、產品名稱、數量、交期、原料齊料日、包材/物料齊料日。
- `製造效能`：建議工作表為 `製造效能_BOM回推` 或 `製造效能`。至少要能提供核心六碼/產品代號、攪料程序、製程設備、製造批次、預攪分鐘、攪料分鐘、清洗分鐘。
- `充填效能`：建議工作表為 `充填效能_BOM回推` 或 `充填效能`。至少要能提供核心六碼/產品代號、工作類型、機器、排瓶時數、充填時數、表定產能人數。

按下 `檢查輸入資料` 後，介面會檢查 `calendar_capacity.xlsx` 是否可讀，也會同步檢查內建基礎 workbook 是否含有這三類工作表，避免打包資料缺漏時無聲失敗。
若需要提供給業主或資料整理人員，也可以按 `匯出輸入格式說明` 產生一份 CSV 版格式說明。

`calendar_capacity.xlsx` 的欄位固定為：

- `日期`：可用 Excel 日期或序號。
- `星期幾`：供人工檢查。
- `是否假日`：填 `假日` 時不排程，填 `平日` 時可排程。
- `充填人力`：當日充填/排瓶可用人數。
- `製造人力`：當日製造可用人數。
- `註解`：可記錄國定假日、補班日或特殊產能說明。

GUI 也提供 `排除週六日` 勾選。若勾選，即使 `calendar_capacity.xlsx` 沒有標成假日，週六日也會排除；若取消勾選，則以日曆表中的 `是否假日` 為主。

### 開發者設定與業主規則
GUI 的 `開發者設定` 頁籤已把業主最新回饋做成可視覺化調整的欄位：

- `資料來源`：目前正式可用為本機 Excel，Google Sheets 先保留串接入口。
- `排程邏輯`：GUI 固定使用 `完整連動排程`，也就是製造必須先於充填，排瓶安排在充填前一個工作日。
- `訂單基礎 workbook`：預設使用打包內建 `workbook_bom_refresh.xlsx`；企業若有自己的訂單/BOM 基礎資料，可在這裡替換。
- `製造效能表`、`充填效能表`：選填。若企業另外提供效能表，可在 GUI 直接指定；空白時使用基礎 workbook 內建的 `製造效能_BOM回推` 與 `充填效能_BOM回推`。
- `產能日曆 calendar_capacity`：固定讀取每日是否可排、製造人力與充填人力。
- `排除週六日`：搭配日曆表，避免排到週末或業主指定假日。
- `凍結排程 CSV`：保留給大量匯入使用。
- `手動凍結排程`：可直接在 GUI 新增一筆或多筆訂單、工序、日期與備註，不需要使用者自己寫 CSV。
- `每日重排時間`：預設 `16:00`，對應業主希望每天 16:00 重新產生明日工單。
- `休息開始`、`休息結束`：預設 `12:00` 到 `13:00`，此區間不會安排任何製造、排瓶或充填任務；精確時間表會自動跳過休息時段並往後銜接。
- `換線分鐘`：可先設定為 `60` 測試一小時換線情境。
- `拆單單位` 與 `最小充填量(L)`：目前先記錄 10 倍數與 50L 的限制假設。
- `小噴印機數量`、`正常噴印機數量`：對應業主提到的一台小噴印機、一台正常噴印機。
- `拆單後日期盡量連續`：已接入 GA 軟性目標；勾選時會降低拆到不相鄰工作日的排法優先順序。
- `輸出派工週視圖`：產生接近 calendar 週畫面的派工摘要。

目前這些設定會寫入 `run_metadata.csv`。其中完整連動排程、外部製造/充填效能表、`calendar_capacity.xlsx`、排除週六日、休息不可排班、換線分鐘、凍結排程 CSV、GUI 手動凍結排程與拆單連續性偏好已接入 GA；拆單單位、最小充填量與噴印機數量仍先作為後續限制入口，目的是讓開發者與業主能用同一組欄位討論下一版限制。

程式內部已把這些欄位統一收斂到 `SchedulerAdvancedOptions`。GUI、命令列、metadata 與交付用輸出都會先經過同一層標準化，再傳入 GA。後續若要新增 Google Sheets 串接、四小時區塊、凍結確切時段或更細的噴印機限制，建議先加在這一層，避免同一個參數散落在多個流程中。

### 合理訂單一定排完
目前正式版的交付原則是：合理訂單一定要排進派工表；不合理或在目前產能日曆下造成硬性衝突的訂單，不會為了湊數硬排。

系統會用三層方式處理：

- 第一層是輸入前檢查：如果 ready date 晚於交期、沒有可用排瓶日前置日、沒有可用製造工作日，會先進 `order_anomalies.csv`，不進 GA。
- 第二層是 GA 排程：所有通過第一層檢查的訂單都會進入完整連動排程，製造必須先於充填，排瓶必須在充填前一工作日或業務允許的同天例外。
- 第三層是交付驗證：合理訂單若在正常日內時段放不下，系統會延長當日確切排程時間並把增加的工時反映到加班與風險檢查，不會把合理訂單移出排程。

正式 demo 時可用 `排程檢查報告.xlsx` 或 `04_輔助檢查資料.xlsx` 檢查兩件事：`error_count = 0`，以及 `可排訂單排入狀態 = 全部可排訂單已排入`。目前排除清單只應包含資料窗本身不合理或日期窗無解的訂單。

### 手動凍結排程
若要固定特定訂單在特定日期，最直覺的方式是在 `開發者設定` 頁籤的 `手動凍結排程` 區塊直接新增。可一次新增多筆，每筆包含：

- `訂單`：例如 `P001`。
- `工序`：可選 `預攪`、`攪料清洗`、`排瓶`、`充填`。
- `日期`：格式 `YYYY-MM-DD`。
- `時間/備註`：目前作為備註與人工溝通欄位；GA 仍以日層級排程為主。

如果未來要大量匯入，也可以繼續使用 `凍結排程 CSV`，或按 `匯出範本` 產生模板。

凍結 CSV 欄位：

- `order_id`：訂單編號，例如 `P001`。
- `stage`：工序，可填 `預攪`、`攪料清洗`、`排瓶`、`充填`，也可填 `Cat1` 到 `Cat4`。
- `date`：指定日期，格式為 `YYYY-MM-DD`。
- `note`：備註，可空白。

目前支援：

- 凍結 `充填`：該訂單充填會嘗試固定在指定日期。
- 凍結 `排瓶`：該訂單排瓶會嘗試固定在指定日期，充填需在隔天或允許同天情境。
- 凍結 `攪料清洗`：製造端攪料日固定，預攪會自動排在前一天。
- 凍結 `預攪`：預攪日固定，攪料清洗會自動排在隔天。

每次排程會輸出 `frozen_schedule_audit.csv`，並在 `交付用輸出/04_輔助檢查資料.xlsx` 的 `凍結排程稽核` 工作表彙整給業主檢查。若日期窗或容量不足，狀態會顯示未套用或日期不符。

### 一小時換線估算
若在 `開發者設定` 中把 `換線分鐘` 設為 `60`，程式會用以下方式估算充填換線：

- 同一天、同一台充填機若只做 1 種產品，換線次數為 0。
- 同一天、同一台充填機若做 N 種不同產品，推估換線次數為 `N - 1`。
- 換線分鐘會被加入充填端每日負荷，並影響 `充填超時分鐘數`、`總加班分鐘數` 與 GA objective。
- 程式會額外輸出 `filling_line_change_audit.csv`，並在 `交付用輸出/04_輔助檢查資料.xlsx` 的 `充填換線稽核` 工作表彙整，方便檢查哪些日期/機台造成換線。

換線分鐘目前仍是 GA 的日層級估算。確切時間輸出已會檢查機台與共用人力是否能排入 5 分鐘時段，也會避開每日休息時間；換線間隔、四小時區塊與凍結確切時段仍需在下一版一起接進日內 sequencing。

### 派工週視圖
若 `開發者設定` 中勾選 `輸出派工週視圖`，程式會產生：

- `dispatch_week_view.csv`
- `交付用輸出/02_當日排程確切時間.xlsx` 的 `派工週視圖` 工作表

這份表是一列一週、欄位為星期一到星期日。每個日期格會摘要：

- 當天有哪些工序。
- 當天涉及哪些訂單與品項。
- 當天機器分鐘與人力分鐘。
- 是否有凍結任務。
- 是否有換線分鐘。
- 是否有超時提醒。

目前週視圖是給業主/派工人員快速閱讀用的日層級 calendar 摘要，不代表精確到每個 5 分鐘時段。若未來要做更細，可以再把它升級成四小時區塊或實際時段排程。

## 打包成安裝包
維護者可以用下面方式建立 Windows 發行版：

```powershell
build_installer.bat
```

或手動執行：

```powershell
python -m pip install -r requirements-build.txt
python -B build_installer.py
```

打包結果：
- `dist/FactoryGAScheduler_latest/FactoryGAScheduler.exe` 或最新的 `dist/FactoryGAScheduler_latest_YYYYMMDD_HHMMSS/FactoryGAScheduler.exe`：新版可攜版，整個資料夾給使用者即可直接執行。
- `installer/FactoryGAScheduler_portable_latest.zip`：新版可攜版壓縮檔，適合直接交付或上傳雲端。
- `installer/FactoryGAScheduler_SelfExtracting_Setup_latest.exe`：若沒有 Inno Setup，會用 Windows 內建 IExpress 產生備用自解壓啟動包。使用者雙擊後會解壓到 `%LOCALAPPDATA%\FactoryGAScheduler` 並啟動程式。
- `installer/FactoryGAScheduler_Setup.exe`：若電腦有安裝 Inno Setup 6，會額外產生正式安裝精靈。

注意：
- 一般使用者只需要安裝包或可攜版，不需要 Python、不需要打開原始碼。
- 打包版會一併包含 `workbook_bom_refresh.xlsx`、`calendar_capacity.xlsx` 與 `README.md`，安裝後 GUI 會自動使用內建基礎 workbook；使用者通常只需要重新選擇 `calendar_capacity.xlsx`。
- 打包腳本會先在系統暫存資料夾建立乾淨版本，再複製成 `latest` 輸出，避免 OneDrive 鎖住舊 `dist/FactoryGAScheduler` 造成覆蓋失敗。
- 若看到舊的 `dist/FactoryGAScheduler` 或沒有 `_latest` 的自解壓檔，可能是先前打包留下的歷史檔；demo 與交付請優先使用 `latest` 版本。
- 若沒有 Inno Setup，正式安裝精靈不會產生，但仍可使用 `FactoryGAScheduler_SelfExtracting_Setup_latest.exe` 作為一鍵啟動交付檔。
- GUI 內也有 `打包安裝包` 頁籤，可以從畫面直接啟動同一套打包流程。

## 目前已落實的重點規則
- 目前不再額外用「交期是否落在 2023/02~2023/08」排除訂單；只要資料本身可排，模型就會嘗試排進去。
- 調製與充填人力分開計算，不共用。
- 若產品流程包含預攪，預攪必須在攪料前一個可工作日；不需要預攪的合法製程可直接安排攪料/清洗。
- 排瓶原則上必須在充填前一天。
- 若啟用 `calendar_capacity.xlsx`，前一天會改成「前一個可工作日」，避免跨週末或假日排到不可工作日。
- 排瓶最多兩人，排瓶人力變動會等比例影響速度。
- 依目前正式規則，預設採用完整連動拉式排程：先反推充填，再安排前一個工作日排瓶，並要求製造在同訂單充填前完成。
- 排程採拉式邏輯優先，會盡量從交期往前找可行日期；若正常容量下找不到位置，會保留排入但加上懲罰，避免可排訂單直接消失。
- GA 初始族群包含依包裝日期窗剩餘彈性排序的拉式種子，優先保護日期窗緊且需求量大的訂單。
- 固定產能日曆可排除週六日、國定假日或自訂假日，並可讀取每日製造/充填人力。
- 每日休息時間可在 GUI 或命令列設定；預設 `12:00-13:00`，製造、排瓶與充填都不會排進此區間，確切時間輸出會自動從休息後繼續銜接。
- decoder 評估排瓶日期時，已改用和正式摘要一致的排瓶工作量基準，避免局部排程看似可行但最後排瓶超時偏高。
- 調製、排瓶與充填會以 5 分鐘時段檢查同時使用的人力與機台；無法配置的任務會成為阻擋交付的錯誤。
- 勾選 `拆單後日期盡量連續` 時，GA 會對跨不相鄰工作日的充填安排加上軟性懲罰，並在拆單時優先選相鄰工作日。
- 加班以分鐘計算，並分開統計調製、排瓶、充填。
- 對外輸出的排程表已統一改成整數顯示，避免出現 `1.5 人`、`0.4 批` 這類業務上不自然的數字。
- 對外輸出的排瓶/充填明細會先做「同日、同訂單、同工序」合併，避免同一批次在報表上被切成許多碎片。
- validation 會把硬性違規 `error` 與人工提醒 `warning` 分開；超過每日最大人力、機器、月加班上限，或無法產生符合日內人力/機台限制的確切時段，都會成為阻擋交付的 `error`；同一訂單充填日期不連續目前屬於 `warning`。
- 會先偵測明顯無解的異常訂單，並輸出 anomaly 清單。
- 若來源訂單缺少可建立模型的製造或充填工序，會輸出 `input_model_issues.csv`，不再靜默略過。
- 會輸出 schedule validation，確認正式結果是否仍有違反核心規則。
- 已加入輕量版的調製換產品清洗 penalty，引導排程避開高切換日。

## 演算法流程
1. 載入訂單與來源資料。
2. 建立初始族群：包含依交期、物料齊料、原料齊料、負荷排序與隨機打散的解。
   其中也包含包裝日期窗剩餘彈性最小優先的拉式種子。
3. 將每一條染色體送進 `GreedyScheduleDecoder`。
4. 依序安排調製、排瓶、充填。
5. 計算：
   - 總加班分鐘數
   - 不可行懲罰
   - 目標懲罰
6. 透過選擇、交配、突變反覆演化。
7. 輸出最佳可行排程與各類檢查表。

## 建議使用方式
正式版執行範例：

```powershell
$env:PYTHONIOENCODING='utf-8'
python -B genetic_algorithm.py --workbook "workbook_bom_refresh.xlsx" --output-dir ga_output_formal_cn --generations 120 --population-size 40 --seed 42 --calendar-capacity "calendar_capacity.xlsx" --break-start 12:00 --break-end 13:00
```

進階命令列參數：
- `--line-change-minutes 60`：加入同日同機台不同產品的一小時換線估算。
- `--break-start 12:00 --break-end 13:00`：設定每日不可排班休息時間。
- `--frozen-schedule-csv frozen_schedule.csv`：讀取手動凍結排程。
- `--calendar-capacity calendar_capacity.xlsx`：讀取固定產能日曆、假日與每日人力。
- `--manufacturing-efficiency path.xlsx`：選填，使用外部製造效能表覆蓋基礎 workbook 內建效能。
- `--filling-efficiency path.xlsx`：選填，使用外部充填效能表覆蓋基礎 workbook 內建效能。
- `--allow-weekends`：若日曆表沒有標成假日，允許週六日排程；不加此參數時會排除週六日。
- `--no-week-view`：若只想產生核心 CSV，可關閉 `dispatch_week_view.csv`。

補充：
- 程式現在會自動在 `output-dir` 後面加上執行當下的日期時間，例如 `ga_output_formal_cn_20260419_153000`。
- 這樣每次測試與正式版輸出都會保留，不會互相覆蓋。
- 主控台摘要也會同步顯示本次執行時間，輸出資料夾內則會另存 `run_metadata.csv`。
- 對外 CSV 與主控台摘要中的總加班分鐘數，現在都會統一顯示為整數。
- 若使用 `calendar_capacity.xlsx`，建議先用 quick run 檢查是否仍有 `task_on_holiday` 之類的 error；目前測試已確認可排除假日且固定格式報告會產生。
