# 工廠訂單排程遺傳演算法說明

## 專案目標
這個專案的目標，是根據業主提供的訂單、BOM、製造效能、充填效能、機器限制與會議整理規則，建立一套可以快速重排的工廠排程程式。

目前演算法核心採用遺傳演算法（GA）：
- 染色體代表訂單排序
- 解碼器依排序逐張訂單安排調製、排瓶、充填日期
- 適應度以總加班分鐘數加上各類懲罰組成
- 先求可行，再逐步優化加班與排程品質

## 主要資料來源
程式目前會綜合使用下列工作表與整理資料：
- `時間準備表V1`
- `2023訂單資訊`
- `BOM`
- `製造效能`
- `充填效能`
- `機器限制`
- `加班計算`
- `欄位說明`

目前做法不是完全拋棄原本模型，而是保留既有 GA 骨架，逐步讓原始資料接管建模與限制。

## 目前已落實的重點規則
- 調製與充填人力分開計算，不共用。
- 預攪必須在攪料前一天。
- 排瓶原則上必須在充填前一天。
- 排瓶最多兩人，排瓶人力變動會等比例影響速度。
- 加班以分鐘計算，並分開統計調製、排瓶、充填。
- 對外輸出的排程表已統一改成整數顯示，避免出現 `1.5 人`、`0.4 批` 這類業務上不自然的數字。
- 對外輸出的排瓶/充填明細會先做「同日、同訂單、同工序」合併，避免同一批次在報表上被切成許多碎片。
- 會先偵測明顯無解的異常訂單，並輸出 anomaly 清單。
- 會輸出 schedule validation，確認正式結果是否仍有違反核心規則。
- 已加入輕量版的調製換產品清洗 penalty，引導排程避開高切換日。

## 演算法流程
1. 載入訂單與來源資料。
2. 建立初始族群：包含依交期、物料齊料、原料齊料、負荷排序與隨機打散的解。
3. 將每一條染色體送進 `GreedyScheduleDecoder`。
4. 依序安排調製、排瓶、充填。
5. 計算：
   - 總加班分鐘數
   - 不可行懲罰
   - 目標懲罰
6. 透過選擇、交配、突變反覆演化。
7. 輸出最佳可行排程與各類檢查表。

## 主要輸出檔案
### 1. `best_schedule_tasks.csv`
任務明細表。適合快速檢查每張訂單每天做了哪些作業。

主要欄位：
- `訂單`
- `類別`
- `明細`
- `日期`
- `機器類型`
- `機器分鐘`
- `人力類型`
- `人力分鐘`

### 2. `best_schedule_reference_format.csv`
業主簡報格式對照表。這份表最接近報告展示用途。

補充：
- 這份表目前以 5 分鐘時段為單位整理充填與排瓶作業。
- 為了讓業主與組員更容易檢查，欄位中的需求量、當日安排量、作業總時間皆以整數輸出。
- 若內部解碼過程曾出現同日碎片化切分，輸出前會先合併成單一列。

主要欄位：
- `訂單編號`
- `子任務編號`
- `工序代碼`
- `工序順序`
- `作業項目`
- `作業工序`
- `人力別`
- `機台別`
- `標準配置人數`
- `總需求量`
- `當日安排量`
- `每單位時間(min)`
- `排程日期`
- `時段範圍`
- `時段數`
- `排程類型`
- `作業總時間(min)`
- `需求單位數`
- `最早時段索引`
- `最晚時段索引`

補充：
- `最早時段索引`、`最晚時段索引` 是把一天切成 5 分鐘一格後的索引位置。
- 例如索引 `0` 代表 `09:00` 開始。

### 3. `schedule_summary.csv`
正式摘要表，用來直接看加班結果。

主要欄位：
- `總加班分鐘數`
- `調製超時分鐘數`
- `排瓶超時分鐘數`
- `充填超時分鐘數`
- `週末加班分鐘數`
- `總排瓶分鐘數`
- `總充填分鐘數`

### 4. `best_schedule_daily_load.csv`
每日人力負荷表。

主要欄位：
- `日期`
- `人力類型`
- `已用人力分鐘`
- `正常人力分鐘`
- `超時分鐘`

補充：
- 這份表目前已改成和正式摘要一致的 overtime 口徑。
- `調製` 以調製人力分鐘計算。
- `排瓶` 以排瓶作業分鐘基準計算。
- `充填` 以充填機台分鐘基準計算。

### 5. `daily_manufacturing_schedule.csv`
每日調製排程表。用來檢查調製每天是否安排過滿。

### 6. `daily_packaging_schedule.csv`
每日排瓶與充填排程表。用來檢查排瓶/充填的每日分布與超時分鐘。

### 7. `manufacturing_cleaning_audit.csv`
調製清洗檢查表。用來估計同日同機器的換產品清洗次數。

### 8. `order_anomalies.csv`
異常訂單清單。會列出排除或警示的訂單。

### 9. `schedule_validation.csv` / `schedule_validation_summary.csv`
排程驗證結果。正式版應優先追求 `validation = 0`。

### 10. `order_source_links.csv`
來源資料對照表。用來追蹤 `Pxxx` 訂單與原始資料的匹配情況。

### 11. `order_model_audit.csv`
建模稽核表。用來查看每張訂單目前套用了哪些來源資料與模型參數。

### 12. `欄位備註表/`
每次正式輸出時，程式會額外自動生成一個 `欄位備註表` 資料夾。

內容包含：
- `欄位備註總表.csv`：彙整所有輸出表單的欄位說明。
- `各表單名稱_欄位備註表.csv`：逐表提供繁體中文欄位用途、判讀方式與合理性檢查重點。

用途：
- 幫助組員、老師與業主理解每一個欄位在模型中的意義。
- 協助人工檢查排程是否合理，而不是只看數字大小。

## 目前判讀原則
- 第一優先：`排程驗證問題數 = 0`
- 第二優先：`不可行懲罰 = 0`
- 第三優先：在可行前提下，降低總加班分鐘數
- 第四優先：讓輸出格式接近業主投影片與報告需求

## 目前已知限制
- 調製清洗規則目前仍是輕量 penalty，不是完整硬限制。
- 部分來源訂單仍需持續補強映射。
- 主控台摘要文字仍有部分歷史中文輸出，CSV 輸出已優先整理為可讀中文。

## 建議使用方式
正式版執行範例：

```powershell
$env:PYTHONIOENCODING='utf-8'
python -B genetic_algorithm.py --workbook "..\2023訂單資訊&產能表-0319.xlsx" --output-dir ga_output_formal_cn
```

補充：
- 程式現在會自動在 `output-dir` 後面加上執行當下的日期時間，例如 `ga_output_formal_cn_20260419_153000`。
- 這樣每次測試與正式版輸出都會保留，不會互相覆蓋。

若只想快速檢查格式或欄位名稱，可用較少代數的 quick run：

```powershell
$env:PYTHONIOENCODING='utf-8'
python -B genetic_algorithm.py --workbook "..\2023訂單資訊&產能表-0319.xlsx" --output-dir ga_output_terms_check --generations 1 --population-size 3
```
